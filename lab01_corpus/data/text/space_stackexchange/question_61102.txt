Osculating conic orbital elements: Comparing SPICE's oscelt to MATLAB's ijk2keplerian functions
I have been using the SPICE Toolbox and wanted to derive orbital elements from a state vector $X$ in ECEF coordinates [1] in order to define a circular orbit around Earth. To do so I need first transform $X$ from ECEF to ECI coordinates [2] and then compute the osculating conic orbital elements in the inertial J2000 frame.
Using the Aerospace Toolbox in MATLAB for instance, this calculation is straightfoward with the combination of the ecef2eci function [3] for the transformation and the ijk2keplerian function [4] to get the corresponding orbital elements.
I have tried to do the very same using SPICE functions: sxform [5] for the transformation and oscelt [6] for the orbital elements. The code is available below.
In both cases the transformation returns states that are similar in order of magnitude and direction. However, the orbital elements, and the eccentricity in particular are very different. In the Table below, one can see that oscelt returns an eccentricity well above 1 whereas ijk2keplerian returns an eccentricity very close to 0, which is expected (circular orbit).
The eccentricity should be close to 0 but it is instead closer to 10^9 which does not make any sense for a circular orbit, or any realistic near-earth orbit. I come to you for help. How does one use this SPICE oscelt function to get realistic orbital elements from an inertial state vector? This tool is well known and proven across many languages, so I fail to see my misuse of this function on such an easy example.
My code and a few references are shared below.

Code
close all;
clear all;
clc;
format bank
%% Add paths to src/mice and lib directories of MICE toolkit
% Source: https://naif.jpl.nasa.gov/naif/toolkit_MATLAB_PC_Windows_VisualC_MATLAB9.x_64bit.html
addpath ('.\mice\lib');
addpath ('.\mice\src\mice');
%% Load SPICE Kernels
% Source: https://naif.jpl.nasa.gov/pub/naif/generic_kernels
cspice_furnsh('.\kernels\de440.bsp');
cspice_furnsh('.\kernels\naif0010.tls');
cspice_furnsh('.\kernels\earth_latest_high_prec.bpc');
cspice_furnsh('.\kernels\Gravity.tpc');
%% Parameters in ECEF
utc_0 = [2019 1 4 12 0 0];
date_0 = sprintf('%i-%i-%i %i:%i:%i UTC', utc_0(1), utc_0(2), utc_0(3), utc_0(4), utc_0(5), utc_0(6)); % EDIT: TDB to UTC
t_0 = cspice_str2et(date_0); % Ephemeris time, s
r_ecef = [-5762640 -1682738 3156028]; % Position in ECEF, m, EDIT: km to m
v_ecef = [3832 -4024 4837]; % Velocity in ECEF, m/s, EDIT: km/s to m/s
%% MATLAB
[r_eci, v_eci] = ecef2eci(utc_0, r_ecef, v_ecef, 'pm', polarMotion(mjuliandate(utc_0), 'action', 'none')*180/pi) % State in ECI, m and m/s
[a_1, ecc_1, incl_1, RAAN_1, argp_1, ~, ~, ~, ~] = ijk2keplerian(r_eci, v_eci); % MATLAB orbital elements
ecc_1 % Eccentricity, 1
a_1 % Semi-major axis, m
incl_1 % Inclination, deg
RAAN_1 % Longitude of the ascending node, deg
argp_1 % Argument of periapsis, deg
%% SPICE
STM = cspice_sxform(char("ITRF93"), char("J2000"), t_0); % State Transformation Matrix from ECEF to ECI
% EDIT: STM for states in m|m/s
% ITRF93 more accurate than IAU_EARTH for ECEF data
X_eci = STM*[r_ecef'; v_ecef'] % State in ECI, m and m/s
mu = cspice_bodvrd( 'EARTH', 'GM', 1 ); % Gravitational parameter for Earth, km^3/s^2
elts = cspice_oscelt(X_eci, t_0, mu*1e9); % SPICE orbital elements, EDIT: GM from km^3/s^2 to m^3/s^2
ecc_2 = elts(2) % Eccentricity, 1
a_2 = elts(1)/(1-ecc_2) % Semi-major axis, m
incl_2 = elts(3)*cspice_dpr % Inclination, deg
RAAN_2 = elts(4)*cspice_dpr % Longitude of the ascending node, deg
argp_2 = elts(5)*cspice_dpr % Argument of periapsis, deg
%% Clearing SPICE kernels
cspice_kclear;
