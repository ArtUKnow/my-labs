Propagating orbit found through Lambert solver leads to a different terminal state
I have recently found cases for which calculating a Lambert transfer orbit and then propagating the resulting (Keplerian) orbit until the time of the terminal position results in a final state quite different than the terminal state provided as boundary condition to solve Lambert's problem.
I have tested different starting conditions and algorithms, and it seems that the difference is quite sensitive to the time of flight, the specific Lambert solver and the Kepler orbit propagator.
For example, the code below reproduces a case with considerable differences under some conditions (sorry for the low quality code, just put this together very quickly!):

import numpy as np
import poliastro.core.propagation as propagation

r2 = np.array([-20434302181.52673000000000000000, 36873458519.50676000000000000000, 498578.57136361836000000000])
tof = 129600.00000000000000000000
v1_izzo, v2_izzo = lamberthub.izzo2015(mu, r1, r2, tof, 0, prograde=True)
# fails to converge: v1_vallado, v2_vallado = lamberthub.vallado2013(mu, r1, r2, tof, 0, prograde=True, maxiter=3500))
v1_arora, v2_arora = lamberthub.arora2013(mu, r1, r2, tof, 0, prograde=True)
v1_avanzini, v2_avanzini = lamberthub.avanzini2008(mu, r1, r2, tof, 0, prograde=True)
v1_gooding, v2_gooding = lamberthub.gooding1990(mu, r1, r2, tof, 0, prograde=True)
v1_battin, v2_battin = lamberthub.battin1984(mu, r1, r2, tof, 0, prograde=True)
# fails to converge: v1_gauss, v2_gauss = lamberthub.gauss1809(mu, r1, r2, tof, 0, prograde=True, maxiter=3500)
f, g, fdot, gdot = propagation.vallado(mu, r1, v1_izzo, tof, 35)
prop_position_vallado = f * r1 + g * v1_izzo
prop_velocity_vallado = fdot * r1 + gdot * v1_izzo
diff_position_izzovallado = r2 - prop_position_vallado

prop_position_cowell, prop_velocity_cowell = propagation.cowell(mu, r1, v1_izzo, [tof])

For these specific boundary conditions, when using Vallado's Keplerian propagator, the errors in the terminal position/velocity are quite large for all Lambert solvers. When using Cowell's propagator, errors are smaller for all solvers, but vary a lot between solvers (e.g., position error <10 m for Izzo and Gooding Lambert solvers, in the order of 1e4 for Avanzini and Battin solvers, and over 1e6 for Arora solver).
What could be the cause of this?
