Why is there a discrepancy between ecliptic longitudes found with Skyfield and Astrolog for old dates?
Just to preface this, I know that Astrolog is software meant for astrology, which is pseudoscientific nonsense; however, I have a friend who insists on using it for certain astronomical calculations (yeah, don't ask me why), and who is asking about why there seems to be a difference between some values it returns and some values I get using Skyfield and JPL's DE422 ephemeris. Astrolog itself is using the Swiss Ephemeris, which supposedly should have a precision of under 1 arcsecond for the bodies in question for the date in question.
For anyone interested in actually checking for themselves in Astrolog, the simplest way to get the values in question would be to go to Info -> Set Chart Info and plug in the date in question (1859-08-23, 3:20 PM, time zone UTC and longitude and latitude of 0), Setting -> Include Minors to get Juno, and Display Settings -> 360 Degrees to show the ecliptic longitude on the right hand side in degrees. The chart itself can be ignored completely, the only thing I'm interested in are these longitudes.
With the above it should now say that the ecliptic longitude of Pluto is 38.504 and that of Juno is 216.504. However, when I use Skyfield to do observations like these I get different values:
t = ts.utc(1859, 8, 23, 15, 20)
ep = earth.at(t).observe(pluto).ecliptic_latlon('date')[1].degrees
ej = earth.at(t).observe(juno).ecliptic_latlon('date')[1].degrees
Here I get an ecliptic longitude for Pluto of 38.502 and one for Juno of 217.322; these are of course fairly close, but they're evidently not the same. What gives? The value for Pluto is particularly close, but still just enough off that I assume there's something wrong. The Juno one is almost an entire degree off, which I really don't get.
Is there something the Astrolog program itself is doing wrong? As far as I'm aware it's just using the Swiss Ephemeris, which should be just as accurate as the DE422 ephemeris used by Skyfield here, but maybe it's not for some reason? Is there something else which has gone wrong here that I'm not thinking of? I guess maybe someone more seasoned could check for themselves what the ecliptic longitudes of the bodies in question should be on that date and time, and compare it to what's been found here.
Addendum:
Accounting for the fact that Horizons uses apparent positions rather than astrometric ones for ecliptic longitude, and UT1 rather than UTC for dates before 1962, I used this to get the ecliptic longitudes instead:
t = ts.ut1(1859, 8, 23, 15, 20)
ep = earth.at(t).observe(pluto).apparent().ecliptic_latlon('date')[1].degrees
ej = earth.at(t).observe(juno).apparent().ecliptic_latlon('date')[1].degrees
This yielded 38.50416 for Pluto, which is in agreement to 3 decimals (off by just 0.00008, less than an arcsecond, that's fine), but the error for Juno persists, as I get 217.31988, still roughly 0.8 degrees off. This is simply too large to be accounted for by the difference in apparent and astrometric, or the leap seconds of difference between UT1 and UTC. I read that the MPC orbital elements being used to compute the position for Juno should have precision to five digits, so I'm very confused as to what exactly is going wrong when that position is computed.
