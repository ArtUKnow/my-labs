Ганяк Александр Олегович · М8О-408Б-23.

Основной корпус: **32 491 уникальная научная статья**, минимум 3 000 английских слов основного текста, 11 журналов по физике высоких энергий. SCOAP³ служит общим репозиторием доставки, источники публикаций — отдельные журналы. Таблица происхождения: `lab1_corpus/data/provenance/scoap3.tsv`; описание источников: `sources.json` в той же папке. Уникальность набора в учебной группе нужно подтвердить у преподавателя.

Основные компоненты теперь написаны на **C++17 без STL**. Собственные массивы, хеш-таблицы, сортировка слиянием, куча и операции над постингами находятся в `native/`. Использованы C/POSIX для файлов, памяти и времени; zlib только для чтения gzip. Python используется для робота, HTTP-оболочки, запуска проверок и подготовки данных. Поисковые запросы и метрики обрабатывает C++.

## Быстрый запуск

Нужны C++17, make, zlib development headers, Python 3.9+. На macOS достаточно Command Line Tools; на Ubuntu: `g++ make zlib1g-dev python3`. `pdftotext` нужен только для извлечения оригинальных PDF.

```sh
make -j2
python3 scripts/package_index.py --extract
printf 'dark matter\n(neutrino || quark) mass\nhiggs !boson\n' | ./build/ir search lab1_corpus/data/native_index --json --limit 50
python3 scripts/web_native.py --port 8000
```

Веб-интерфейс: [http://127.0.0.1:8000](http://127.0.0.1:8000). На странице 50 результатов, заголовки, ссылки и переход к следующей странице. HTTP-оболочка вызывает C++; собственного Python-поиска в основном пути нет.

```sh
bash run_all.sh tests       # C++ fixtures, настоящий CLI/HTTP, робот и полная проверка корпуса
bash run_all.sh build       # пересчитать все нативные результаты по корпусу
bash run_all.sh crawl       # загрузить/проверить сырые оригиналы и HTML в SQLite
```

## Индекс и нормализация

Все четыре окончательных файла индекса бинарные: словарь, постинги, прямой каталог документов и метаданные. Формат с сигнатурой и версией описан побайтово в [native/INDEX_FORMAT.md](native/INDEX_FORMAT.md). Индекс строится блоками, затем сливается; весь корпус одновременно в памяти не хранится. При запросе читаются только нужные списки постингов. Используются И (`&&` или пробел), ИЛИ (`||`), НЕ (`!`), круглые и квадратные скобки.

UTF-8 токенизатор использует таблицы свойств Unicode и собственный декодер. Английский стеммер упрощённый; русский использует правила Портера. Лемматизация — ограниченные правила и исключения, полноценного морфологического словаря нет. Нормализация документа и запроса одинакова. Позиции слов и цитатный поиск в текущий булев индекс не входят.

## Робот и воспроизводимость

Единственный аргумент основного робота — YAML:

```sh
python3 lab2_crawler/crawler.py lab2_crawler/config.yaml
```

`db` задаёт SQLite, `logic` — задержку, число загрузок, таймаут, повтор и интервал переобкачки; `corpus` задаёт тот же каталог статей. В базе сохраняются нормализованный URL, точное исходное тело сжатое без потерь, MIME, журнал, Unix-время фактической загрузки, SHA-256, ETag/Last-Modified. HTML-страница и исходный XML/PDF — два ресурса одной статьи, их количество не выдаётся за количество статей. Очередь восстанавливается после остановки; 304 и совпадение SHA не переписывают исходное содержимое. Изменение ответа проверено настоящим локальным HTTP-тестом; 11 источников в CERN реально проверены условными запросами, результат — `live_recrawl.json`.

Текущий статус полного сырого архива — `lab2_crawler/results/raw_crawl_summary.json`; только `status: complete` с проверенными телами означает завершённую загрузку. Архив базы публикуется отдельно от Git из-за размера. Примеры оригиналов и HTML всех журналов находятся в `lab1_corpus/data/raw_samples/`. После переобкачки:

```sh
python3 lab1_corpus/extract_raw_corpus.py lab2_crawler/data/scoap3_raw.sqlite --apply
bash run_all.sh build
```

Метаданные и ссылки исходных публикаций доступны в [SCOAP³](https://repo.scoap3.org/). Фактические запросы к существующему поиску, время проверки и недостатки выдачи сохранены в `lab1_corpus/results/existing_search.json`.

## Проверка поиска

Все 32 491 статьи участвуют в каждой выдаче. 44 воспроизводимых запроса на поиск известной статьи выбраны по четырём статьям каждого журнала, запрос — часть заголовка, статья-цель подтверждается ссылкой оригинала. Протокол и ограничения: `lab6_search_quality/results/protocol.json`. Это автоматическая проверка идентификации статьи, а не независимая ручная тематическая разметка. При одной цели максимальный P@5 равен 0,2.

Отдельно сравниваются три алгоритма на том же полном корпусе: Boolean AND, TF-IDF и BM25. Формулы записаны в `comparison_metrics.json`, метрики P/R/AP/DCG/NDCG/ERR рассчитаны настоящей C++-программой на уровнях @1/@3/@5. Это сравнение алгоритмов, не результаты внешних веб-поисковиков. Лаба 6 дополнительная; независимая ручная тематическая оценка и сравнение внешних сервисов остаются отдельной работой.

Проверки включают ручные расчёты метрик и TF-IDF/BM25, независимый булев эталон, многоблочную сборку, реальные HTTP-страницы 50/50/21 результатов, ошибки синтаксиса и экранирование. Проверяются также исходные тексты на запрет STL. Санитайзеры и сборка Linux проверяются отдельно, их логи приложены к результатам.
